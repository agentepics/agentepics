**Version 0.5.2**

This page is the entry point to the normative scripting reference for Agent
Epics: `cron.d/`, `hooks/`, and `policy.yml`.

If you need the portable core format, read
[Epic Specification](/epic-specification). If you need the short overview map,
read [Epic Reference](/specification).

## What this reference covers

The scripting surface defines how a compliant host should interpret:

- recurring execution through `cron.d/`
- event-triggered execution through `hooks/`
- autonomous-operation constraints in `policy.yml`
- how scripting features interact with the shared `runtime/` tree

## Scripting compatibility rules

- `runtime/state/core.json` is authoritative over `runtime/state.json`
  whenever `runtime/state/` exists.
- Agents MUST read `policy.yml` at activation time when it exists and treat it
  as hard constraints.
- `SKILL.md` instructions MAY guide interactive work and MAY emulate the spirit
  of a scripting reaction when no scripting feature exists, but they MUST NOT
  replace, mask, or override configured scripting features.
- If a scripting host does not support a scripting feature used by the epic, it
  SHOULD surface that limitation explicitly rather than silently skipping it.
- Scripting hosts MUST tolerate `runtime/` being absent or empty and MAY create
  it lazily.
- The spec does not standardize host-private retry, dedupe, lock, or cache
  storage.

<Warning>
If a scripting feature is present in an epic, a compliant scripting host must
either honor it according to this specification or surface that it does not
support the feature. It must not silently reinterpret scripting features as
advisory prose.
</Warning>

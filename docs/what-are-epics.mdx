---
title: "What are epics?"
description: "A plain-English explanation of Agent Epics and when to use them."
---

An epic is a skill with durable operating state around it.

`SKILL.md` still handles discovery and activation. `EPIC.md` and the optional
files around it let an agent keep plans, facts, logs, outputs, and automation
rules across sessions instead of reconstructing everything from chat history.

## Skill vs epic

| Use a skill when... | Use an epic when... |
|---------------------|---------------------|
| the agent mainly needs reusable instructions | the agent also needs durable state |
| the work fits in one session or handoff | the work will be resumed later |
| there is no live plan to maintain | a current plan should survive over time |
| there is no structured project state | facts should live in files, not memory |
| there is no ongoing automation | hooks, cron jobs, or policy may matter |

## The basic shape

```directory
my-epic/
├── SKILL.md          # Discovery and activation
├── EPIC.md           # Durable operating definition
├── runtime/          # Live state for the current run
│   ├── plans/
│   ├── state.json
│   ├── log/
│   ├── ROADMAP.md
│   ├── DECISIONS.md
│   └── artifacts/
├── hooks/            # Optional event-triggered actions
├── cron.d/           # Optional recurring jobs
├── policy.yml        # Optional hard constraints
├── skills/           # Optional epic-scoped skills
├── scripts/
├── references/
└── assets/
```

Only `SKILL.md` and `EPIC.md` are required. The rest appear as the epic starts
carrying real work.

## What epics are good for

Epics fit work with one or more of these properties:

- it spans many sessions
- it needs a durable current plan
- it accumulates decisions, outputs, and approvals
- it benefits from structured state
- it may run recurring or event-driven automation
- the operating model should be reusable later

## What epics are not

An epic is not just "a big task." If the agent only needs instructions and a
few temporary files, a plain skill is usually enough. The value of an epic is
the durable operating surface around the work.

## Common epic shapes

- **Workflow epic**: a reusable process with fresh state each run
- **Instance epic**: one specific long-lived project
- **Capability epic**: an installed ability such as memory, monitoring, or an integration

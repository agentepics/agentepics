Agent Epics is an open format for work that has to survive beyond the current
chat. It keeps the portability of `SKILL.md` and adds the files an agent needs
to keep operating over time: a durable definition, a current plan, structured
state, logs, and optional scripting rules.

Use an epic when the agent should be able to come back tomorrow and still know:
what this work is, what changed, what is blocked, and what it may do next.

## Fast mental model

- A **skill** tells an agent how to do a kind of task.
- An **epic** adds the files that let the agent keep doing that work over time.
- `SKILL.md` is the discovery and activation surface.
- `EPIC.md` is the durable operating definition.
- `runtime/` holds the live working state for the current run.
- `hooks/`, `cron.d/`, and `policy.yml` add optional scripting behavior.

## Why epics exist

Plain skills work well for stable know-how. They break down when the agent also
needs durable memory, a current plan, decision history, or policy-constrained
automation. Epics package those things into one portable operating surface.

[Why state and reuse matter](/stateful-and-reusable) shows the difference in
practical terms. [Epic usage](/epic-usage) shows what an agent actually creates
while working inside an epic.

## Ecosystem foundation

Many agent products already understand `SKILL.md`. That compatibility layer
makes EPIC adoption easier and keeps epics portable across tools.

## Open development

`SKILL.md` was originally developed by
[Anthropic](https://www.anthropic.com/), released as an open format, and
adopted across a growing set of agent products. Agent Epics builds on that
substrate and is maintained here by Kindship.ai.

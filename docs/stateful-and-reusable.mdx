The point of an epic is not that the work is large. The point is that the work
needs to stay understandable and operable over time.

A plain `SKILL.md` can teach an agent what to do. An epic adds the files that
let the agent know where the work stands right now, what changed recently, and
what it is allowed to do next.

## What a skill can do well

A skill is excellent for stable know-how:

- how to write a landing page
- how to prepare a call sheet
- how to clean a dataset
- how to run a recurring process in principle

That is enough when the work does not need durable state.

## What an epic adds

An epic becomes useful when the agent must also preserve:

- the active plan
- structured facts and status
- decisions that should outlive chat history
- recent history across sessions
- optional automation and policy rules

Those needs map directly to files:

- `runtime/plans/` for tactical work
- `runtime/state.json` or `runtime/state/` for machine-readable facts
- `runtime/log/` for durable history
- `runtime/DECISIONS.md` and `runtime/ROADMAP.md` for low-churn context
- `hooks/`, `cron.d/`, and `policy.yml` for scripting behavior

## Example: website relaunch

A skill can explain how to redesign and launch a website. It cannot natively
track that the sitemap was approved last week, the pricing page is blocked on
legal review, and a weekly SEO check should keep running after launch.

An epic can.

```text
website-relaunch/
├── SKILL.md
├── EPIC.md
├── runtime/
│   ├── plans/
│   │   ├── 001-discovery.md
│   │   └── 002-launch-readiness.md
│   ├── state/
│   │   ├── core.json
│   │   └── approvals.json
│   ├── log/
│   └── artifacts/
├── hooks/
├── cron.d/
├── policy.yml
└── references/
```

With a skill alone, the agent knows how to do the work.
With an epic, the agent also knows which website this is, what is left, what
changed, and what automation is allowed.

## Reuse matters too

Reuse means the operating model survives while the live state changes.

The same epic can power:

- this quarter's website relaunch
- the next client's website relaunch
- the next internal site refresh

The stable definition stays in `SKILL.md`, `EPIC.md`, `scripts/`, and
`references/`. The per-run state lives under `runtime/`.

## Rule of thumb

Use a skill for reusable instructions.

Use an epic when you need reusable instructions plus durable operating state.
